# Step 2: 성능 감사

## 작업 내용
- performance.md 기준 점검
- 느린 API 엔드포인트 식별 (P95 기준)
- N+1 쿼리 탐지 및 해결
- 인덱스 누락 컬럼 식별
- 프론트엔드 번들 사이즈 확인 (초기 번들 < 250KB gzip 권장)
- 불필요 리렌더링/메모리 누수 확인
- 캐싱 전략 검토 (브라우저, CDN, 애플리케이션, DB)

## AC (Acceptance Criteria)
- [ ] P95 응답 시간: 단순 조회 < 100ms, 복잡 < 500ms, 쓰기 < 1000ms
- [ ] N+1 쿼리 0건
- [ ] 초기 번들 사이즈 < 250KB (gzip)
- [ ] 메모리 누수 없음 (long-running 프로세스 기준)
- [ ] 캐싱 적용 대상에 TTL 정의
