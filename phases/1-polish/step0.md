# Step 0: 에러 핸들링 정비

## 작업 내용
- 모든 API 엔드포인트에서 일관된 에러 응답 포맷 적용 (api-conventions.md 참조)
- try-catch 누락 지점 식별 및 보완
- 사용자 친화적 에러 메시지 변환 (내부 에러 그대로 노출 금지)
- 글로벌 에러 핸들러/미들웨어 적용
- 로그 레벨 분류: info(정상), warn(우려), error(실패), fatal(중단)

## AC (Acceptance Criteria)
- [ ] 모든 API가 `{ error: { code, message, details } }` 포맷 반환
- [ ] 500 에러에서 내부 정보(스택 트레이스, DB 메시지) 미노출
- [ ] 예측 가능한 에러 시나리오에 대한 사용자 메시지 정의
- [ ] 구조화 로깅 적용 (`[서비스명] 메시지: 내용` 패턴)
