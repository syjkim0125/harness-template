# 성능 규칙

## 모델 선택 (OMC 환경 기준)

> 이 섹션은 oh-my-claudecode 환경에서만 유효하다. OMC를 사용하지 않으면 무시해도 된다.

| 모델 | 용도 |
|------|------|
| **Haiku** | 간단한 조회, 파일 탐색, worker 에이전트 |
| **Sonnet** | 메인 개발 작업, 멀티 에이전트 오케스트레이션 |
| **Opus** | 아키텍처 결정, 복잡한 분석, 보안 감사 |

## 알고리즘 효율

구현 전 확인:
- [ ] 시간 복잡도 고려 (Big O)
- [ ] O(n²) 대신 O(n log n) 또는 O(n) 가능한지 확인
- [ ] 적절한 자료구조 선택 (Map vs 배열, Set vs 배열)
- [ ] 비싼 계산은 캐싱 (memoization)

| 연산 | 목표 | 피할 것 |
|------|------|---------|
| 검색 | O(log n) 또는 O(1) Map | O(n) 선형 탐색 |
| 정렬 | O(n log n) 빌트인 | 커스텀 O(n²) 정렬 |
| 조회 | O(1) Map/Set | O(n) 배열 탐색 |
| 집계 | O(n) 단일 패스 | O(n²) 중첩 루프 |

## 백엔드 성능

### 응답 시간 목표 (P95)
| 타입 | 목표 | 예산 |
|------|------|------|
| 단순 조회 | < 100ms | 캐시 히트 |
| 복잡 조회 | < 500ms | DB 쿼리 + 가공 |
| 쓰기 | < 1000ms | 검증 + DB + 이벤트 |
| 파일 업로드 | < 5000ms | 스트리밍 처리 |

### DB 쿼리 최적화
- **N+1**: JOIN, DataLoader, 배치 쿼리 사용
- **인덱스**: WHERE, ORDER BY, JOIN 컬럼에 인덱스
- **페이지네이션**: 대량 결과는 항상 페이지네이션
- **커넥션 풀링**: 요청마다 새 커넥션 금지
- **목표**: 쿼리당 < 100ms, 요청당 < 10쿼리

### 캐싱
| 레벨 | 대상 | TTL | 무효화 |
|------|------|-----|--------|
| 브라우저 | 정적 자산 | 길게 (1년) | 파일명 해시 |
| CDN | API 응답 | 짧게 (1-60분) | 캐시 태그 |
| 애플리케이션 | 계산 데이터 | 중간 (5-60분) | 이벤트 기반 |
| DB | 쿼리 결과 | 짧게 (1-5분) | 쓰기 시 무효화 |

## 프론트엔드 성능

### 로딩 목표
- **LCP**: < 2.5초
- **CLS**: < 0.1
- **INP**: < 200ms

### 번들
- 초기 번들: < 250KB (gzip)
- 코드 스플리팅: 라우트, 모달, 무거운 컴포넌트 lazy-load
- 미사용 export 제거 (tree shaking)

### 렌더링
- 불필요 리렌더링 방지 (증명된 곳에서만 memo/useMemo)
- 긴 리스트 가상화 (react-window, virtual scroll 등)
- 자주 발생하는 이벤트 debounce/throttle (스크롤, 리사이즈, 입력)

## 성능 모니터링

### 모니터링 항목
- 응답 시간 (P50, P95, P99)
- 엔드포인트별 에러율
- 처리량 (초당 요청 수)
- 리소스 사용률 (CPU, 메모리, 디스크, 네트워크)
- DB 슬로우 쿼리
- 캐시 히트/미스 비율

### 알림 기준
- P95 응답 시간 > 1초
- 에러율 > 1%
- CPU > 80%
- 메모리 > 85%
